# 国标公文：GB/T 9704-2012（附加能力，非核心流程）

> 归属**Office 模块**的附加能力，不是核心流程；工具保留但路由不优先命中。

> 这是**按需附加能力**：只有用户明确说「国标公文 / 红头 / 9704 / 小标宋 / 仿宋」时才用。
> 工具箱的主线是「通讯最近动态与收件催办 / 多科室跨表汇总核表 / 台账与经验」，
> 普通 Word 排版、改格式、写通知一律走 WorkBuddy 原生文档能力，不要往这里引。

`work_office_format_gbt9704` 一把排完。输入可以是 Markdown 草稿、纯文本、普通 Word 路径，
也可以直接把整篇正文塞进 `content_or_path`。

## 硬指标（必须逐条达标，缺一不可）

| 项 | 要求 |
| --- | --- |
| 纸张 | A4 |
| 页边距 | 上 37 mm / 下 35 mm / 左 28 mm / 右 26 mm |
| 标题 | 二号方正小标宋；**缺字体降级华文中宋时必须说明** |
| 正文 | 三号仿宋，固定行距 28 磅，首行缩进 2 字符 |
| 一级标题 | 三号黑体 |
| 二级标题 | 三号楷体 |
| 红头 | 机关标志 + 红色分隔线（报告类默认带） |
| 页码 | 「— 1 —」样式，四号宋体 |

## 参数

| 参数 | 说明 |
| --- | --- |
| `doc_type` | 报告 / 通知 / 请示 / 批复 / 函 / 纪要，影响版头与称谓 |
| `header_unit` | 红头机关名称，如「XX市财政局」 |
| `doc_number` | 发文字号，如「X财〔2026〕12号」 |
| `output_path` | 不给就落 `03_汇总与成稿输出/<原名>_国标排版.docx` |

## 交付前

- 函数内部会用 OfficeCLI `validate` 校验，`success=false` 先修再交付。
- 回复里必须给：产物路径、页数、字体是否降级、红头与页码是否生成。
- 缺字体不是失败，但**不能不说**——用户拿到的可能是华文中宋而非方正小标宋。

## 常见误解

- 公文排版**会写文件**，没有 dry_run，不要说「先预览一下」。
- 排版不改内容：正文里的事实、数字、称谓得先由用户确认。
- 「白头」是不带红头的版本，`doc_type` 选通知/函时按需给 `header_unit`。
