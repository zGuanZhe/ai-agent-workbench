# 把工具箱封装成 WorkBuddy Skill 与斜杠命令（不打开网页也能用）

> **状态补记（2026-11-10 晚）**：后续又做了一轮体验收敛，日常入口已变成**唯一 `/work`**，
> 并新增 `scripts/work.py` 本地桥接——不打开网页、不点 MCP 信任也能调用全部工具；
> `/exp`、`/exp-save`、`/work-setup` 已合并进 `/work`。本文记录的是**当时那次任务**的口径与踩坑，
> 文中「必须点信任」「四条命令」「网页优先」等说法现已不是当前用户流程，照做前请以总 Skill 为准。

## 一句话经验

> 注册 MCP 时**必须实测 `import mcp` 成功**，只测 `docx/openpyxl` 会把服务注册到缺依赖的解释器上；另外项目里叫 `mcp/` 的目录会遮蔽真正的 PyPI 包，`sys.path` 要用 `append` 不能用 `insert(0)`。

## 一、这次要交付什么

让本机工具箱在**不打开控制台网页**的情况下也能完整使用：WorkBuddy 能直接调工具，用户能用 `/` 命令跑流程；换一台机器下载后，一条命令就能装好依赖、连上 MCP、生成网页。

验收标准：新会话里 `/work <需求>` 能跑通；命令行 `run-tool.cmd work_status` 返回 `ok:true`；`setup.cmd` 在缺依赖的机器上能自愈。

## 三、完整流程（照着做）

1. `mcp/dump_tools.py > web/tools.json` 刷新工具清单，`web/build.py` 生成单文件 `console.html`。
2. 写 Skill：`SKILL.md` 讲清「什么时候用、选哪条流程、边界在哪」；`commands/*.md` 一个文件一条斜杠命令。
3. 写 `tools/register_mcp.py`：探测**装齐 `mcp` + docx + openpyxl** 的解释器，把 `work-toolkit` 合并写进 `mcp.json`（只改自己的键，不动别人的 server）。
4. `scripts/setup.cmd` 串起整条链：体检 → 补装缺失依赖 → 注册 MCP → 构建网页 → 跑 3 个工具验收。
5. 用户到 WorkBuddy「连接器 / MCP 管理」对 `work-toolkit` 点**信任**并重载会话——这一步只能人来做。
6. 命令文件是新建的，**重载会话后**才会被识别，别在旧会话里反复试。

## 四、关键口径与决策

- **网页优先、桌面小窗后置**：功能还在持续更新，网页免安装、改完刷新即生效；桌面小窗等稳定后复用同一个 `console.html` 套 webview，不重写前端。
- **入口都不假设 `python` 指向谁**：`launch.py` 用纯标准库启动，再由它挑装齐依赖的解释器；`run-tool.cmd` 首次探测后把路径缓存到 `workspace/.pyexe`。
- **体检脚本自己零依赖**：`doctor.py` 只用标准库，这样「什么都没装」的机器上它也能跑起来告诉用户缺什么。
- **回归脚本长期留存**：`tools/regress.py` 对 21 个工具做 `run / guard / env` 三类冒烟，`--json` 可接 CI，不拿「报错」冒充「跑通」。

## 五、踩过的坑（别再犯）

- **现象**：命令行路径下 21 个工具全部报 `No module named 'mcp'`，但服务内调用正常。
  **根因**：`tools/run_tool.py` 把项目的 `mcp/` 目录 `sys.path.insert(0, ...)`，这个目录被当成命名空间包 `mcp`，把真正安装的库整个遮蔽了；之前的"自检通过"是假阳性。
  **改法**：统一改成 `sys.path.append(...)`；缺依赖时给可执行的中文提示，而不是抛一句看不懂的 ImportError。
- **现象**：旧注册脚本只测 `docx`/`openpyxl`，选中的解释器其实没有 `mcp`。
  **改法**：注册前把 `mcp` 也列为必需项实测 `import`；`doctor --pick` 输出最合适的解释器路径。
- **现象**：`.cmd` 里的 UTF-8 中文注释在 Windows cmd 下被按代码页 936 解析，脚本直接执行不下去；`doctor --pick` 输出的中文用户名路径（如 `C:\Users\<中文用户名>\...`）变乱码。
  **改法**：批处理一律**纯 ASCII + CRLF**，开头 `chcp 65001`，中文提示全部交给 Python 输出。
- **现象**：`python tools/run_tool.py` 每次退出码 139（段错误）。
  **根因**：stdin 是「开着但不写数据」的管道，读取线程卡在 C 层 `read()`，解释器收尾强杀就崩。
  **改法**：`main()` 返回后用 `os._exit(code)` 硬退出（先 flush stdout/stderr）。
- **现象**：构建脚本报的体积比实际文件小两成。
  **根因**：拿字符数当字节数，中文 UTF-8 占 3 字节。
  **改法**：按 `len(html.encode('utf-8'))` 算。
